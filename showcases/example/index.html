SimpleFormJs 2.0

Declare the data once, collect it with a generated form, produce scripts, configurations and documents with templates.

    How this tour works

    Every step introduces one feature with a live demo. Under each demo, Show code reveals the exact code that runs it — copy it into your page and it works the same way.

    To use SimpleFormJs in a page you need three tags:

    <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/bobpuley/SimpleFormJs@2/dist/simpleform.css">
<script src="https://cdn.jsdelivr.net/npm/handlebars@4.7.8/dist/handlebars.min.js"></script>
<script src="https://cdn.jsdelivr.net/gh/bobpuley/SimpleFormJs@2/dist/simpleform.umd.min.js"></script>

    or, with a bundler: import { SimpleForm } from "simpleformjs";

    1. Quick start

    A schema describes the fields; templates describe the outputs. One form can feed many outputs: here an UPDATE script and its ROLLBACK.

    • Type in the fields: the preview updates live.
    • Empty the Airport code: it appears as a highlighted placeholder and Copy / Download are disabled.
    • Type a name with an apostrophe (Charles d'Gaulle): the {{sql}} helper escapes it.

    2. Field types

    Built-in types: text, number, date, textarea, checkbox, select, autocomplete, email, url. Each field has a label separate from its name (the variable used in templates) and an optional help text.

    3. Validation

    Declarative rules: required, pattern, min/max, minLength/maxLength, plus custom functions that can look at the other values. Errors appear once a field has been touched. All messages can be translated through the messages option — this demo uses Italian.

    • Set an end date before the start date.
    • Type a ticket that does not match OPS-1234.

    4. Autocomplete

    The autocomplete type is an accessible combobox: arrows to move, Enter to choose, Esc to close. Options may be { text, value } pairs: the user sees the text, the template receives the value. Free text is rejected unless allowCustom: true. Options can also come from an async function.

    • Type vi in Country and choose Viet Nam: the output gets VN.
    • Type Atlantis and leave the field: you get an error.
    • Airline simulates a server lookup with a 400 ms delay.

    5. Conditional & dependent fields

    visibleWhen shows a field only when a condition holds (hidden fields are neither validated nor passed to templates). dependsOn reloads options when another field changes: from an in-memory map, a function, or a URL with placeholders (optionsUrl: 'data/cities-{country}.json').

    • Choose Italy: the VAT number field appears and is required.
    • Change country: Region (map) and City (fetched JSON) reload.

    6. Helpers & output formats

    Templates are plain Handlebars. Built-in helpers handle escaping and formatting: sql, quote, json, upper, lower, trim, default, now, eq/ne/and/or/not, join. Add your own with SimpleForm.registerHelper. Each template sets its own language (syntax highlighting), filename (itself a template) and mode: text (default, shown as a code block), plain (regular text, e.g. an email) or html (rendered, values still escaped). text and plain are never parsed as HTML.

    7. Presets & persistence

    presets fill in groups of values at once (e.g. per environment). persist: 'url' stores the values in the address bar — Copy share link gives a colleague the form already filled in. persist: 'local' remembers the last values in localStorage.

    • Choose the prod preset, then reload the page: the values are still there (look at the URL).
    • The second form remembers what you type across reloads; Reset forgets it.

    8. Batch & CSV import

    With batch the form becomes a list of rows. Templates with perRow: true are rendered once per row; other templates receive rows and count. Paste a CSV (with or without a header line, comma/semicolon/tab separated) to create many rows at once.

    • Open Import CSV and paste:
      code;name;country CDG;Charles de Gaulle;FR FCO;Leonardo da Vinci;IT MAD;Adolfo Suárez Barajas;ES

    9. Hooks & events

    React to what happens with option hooks (onChange, onRender, onInvalid, onCopy, onError), with form.on(event, fn), or with DOM events (simpleform:change, …) that bubble from the container. Use them to send outputs to an API, log usage, or drive other widgets.

      10. Custom field plugins

      New field types are registered once with SimpleForm.registerField(type, { render, getValue, setValue, validate, update }) and can then be used in any schema. Here a coordinates field made of two inputs.

      11. No-code mode: just markup

      Perfect for wiki or Confluence pages: add data-simpleform to a container, put the configuration in a <script type="application/json" class="sf-schema"> and the templates in <script type="text/templates">. The library initializes it automatically — no JavaScript to write. Templates may be indented freely: common indentation is removed.

      Show code

      The configuration can also live in a separate file: <div data-simpleform data-schema-src="data/airport.json">

      12. Import & export schemas

      SimpleForm.loadSchema(url) loads a JSON configuration; form.exportSchema() turns a live form back into JSON (functions cannot be serialized and are reported in warnings). Schemas become reusable files you can version and share.

      13. "Generate" flow & 1.x compatibility

      Prefer an explicit button? Set livePreview: false: outputs appear after Generate, which validates everything and focuses the first error. Pages written for 1.x keep working through the ScriptGenerator adapter — fieldName/values are mapped, defaultValue now works, and jQuery is no longer needed.
